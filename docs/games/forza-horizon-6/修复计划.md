两份日志首行均为 `OptiScaler(NR) v1.12.0 (35a10f9b) (20261011_174416)`；不是本次开发基线的运行结果。
环境记录为 Windows 11、RX 9070 XT、Streamline 2.11.3，SR 使用 FSR 3.X，FG 关闭。

| 证据 | 结论 | 不可由此推断的内容 |

## 2. 老版本是否存在兼容回退

有可定位的**默认策略变化**：`c4690e587b9d5bedad38caed166dcd21c9222cd5` 把 `LmxxfAllowEnhancedBarriers` 默认值从 true 改成 false，并按 `enhanced_barrier` 拒绝切分。它的理由是当时没有建模 layout/access 和 `SYNC_SPLIT`，不是针对该游戏关闭功能。

因此，“旧版本不手动设置也能运行、新版本默认不运行”有源码解释。但旧版本运行过不等于同步正确。不能简单恢复全局默认 true；本次保留 INI/菜单选择以及默认 false，给显式开启后的路径补齐输入布局处理。

现有 `NrInline` 是独立实验功能，默认 false。其超时或 ahead cap 仍可能选择原图，本次不自动开启它，也不以其规避普通 split 路径的问题。

## 3. 本次源码修改

代码根目录为 `OptiScaler-DLSSNR-PreSR-Multipass-main/OptiScaler/`。

1. **命令列表身份：`dlssnr/submission/CommandListProxy.h`、`inputs/NVNGX_DLSS_Dx12.cpp`。**
   `QueryLogicalCommandList` 首先查询现有逻辑接口；如果外层不转发该接口，使用仓库已有的 Streamline native-object IID 查询一层底层对象，并要求它确实提供逻辑接口。全程持有 COM 引用。不把任意 native list 临时包装为代理，也不按指针相似性建立映射。
   对 OptiScaler 替代 SR 路径，恢复的逻辑代理覆盖 pre-NR、SR 和 post-NR 的整个调用，避免只在 AmdBridge 内切换列表后，SR 仍从外层包装器写入原 producer。原生 DLSS/FG passthrough 分支未改动。
2. **输入布局：`dlssnr/backend/NrInlineRecording.h`、两个后端及 `CommandListProxy.h`。**
   增加 split 用的状态作用域入口。已知完整 enhanced 输入转换至 COMMON，后端按 COMMON 录制 legacy 操作，返回时在当前 continuation 恢复原 layout/access 和游戏绑定。未观察到布局变化的输入沿用 Frame/INI legacy 状态契约，包括前一提交列表已建立的状态；无关 GLOBAL/纹理 barrier 不会使该契约失效，不猜 COMMON。普通 legacy split 不新增输入扫描或私有绑定恢复；enhanced 列表实际输入全为 legacy 时也不建立私有作用域。Mochizuki 不再仅因列表曾出现 enhanced barrier 就通过旧 `CanAppendCompute()` 拒绝；共享后处理的该保护保持不变。
3. **切分前保护：`CommandListProxy.h`、`LogicalList.h`。**
   enhanced 观察使相应旧 legacy 记录失效；legacy aliasing 和部分 legacy 转换保留“未知”记录，不能通过删除记录回落到调用方旧状态。通配 aliasing 同样覆盖此前未观察的资源；完整转换可重建已知状态。所有记录局限当前 recording，Reset 清空，不增加跨列表裸指针缓存。任何看到 `SYNC_SPLIT` 的录制保守拒绝。需要恢复 DXR 或 enhanced 状态时，在关闭 producer 前检查新 continuation 的 List4/List7 支持。
4. **RTAS：`CommandListProxy.h`。**
   按维护者意见撤回初版 Build/EmitPostbuild/Copy AS 的放行，保留基线 `rtas` 拒绝策略。现有日志未证明这些列表就是 NR 列表；放宽策略须另行收集列表身份证据并完成 DXR 回归，不作为本 PR 的前置改动。
5. **取证：`LmxxfBackend.cpp`、`MochizukiBackend.cpp`。**
   两后端都增加限频输入拒绝日志（前 5 次及每 1000 次）：frame、proxy/native 地址、稳定 listId/generation、colour/motion/depth/exposure 角色、整资源输入范围、最近观察范围、layout/access、legacy 状态及失效标记。未知记录中的 last 字段只用于取证。保留 missing recording proxy 日志；Mochizuki 分别记录 logicalQi/resourcesQi。两后端的成功样本记录 frame 和列表身份，供关联成功/失败评估，仍不将代理解包当作已证实的闪烁根因。

字段来源：颜色、motion/depth/exposure 仍来自既有 `AmdPreSr::Frame`；lmxxf 根据 model-history 和可用 exposure 决定消费哪些输入，Mochizuki 根据 temporal/guide 契约决定是否消费 motion。增强布局来自该代理观察的真实 Barrier 参数，不根据资源名称推断。不新增旧 ABI、旧帧颜色或旧 runtime 兜底；失败仍沿用原图旁路。

互操作依据：[Microsoft Enhanced Barriers 规范](https://microsoft.github.io/DirectX-Specs/d3d/D3D12EnhancedBarriers.html#interop-with-legacy-resourcebarrier)。COMMON 互操作不等于完整状态跟踪：若 enhanced 布局仅在另一列表建立，当前代理无法发现；未观察输入要求调用方提供有效的 legacy 互操作状态。后续若需跨列表跟踪，必须同时设计资源生命周期、队列提交顺序和子资源范围，不能直接复用录制时的全局状态表。

## 5. 游戏验收顺序

每轮用同一存档/天气/固定场景，记录源码 SHA、完整包版本、驱动、分辨率、SR/NR 配置。先固定 render resolution、单 pass、关闭 FG 和额外 NR 后处理，减少变量。保留原用户 INI 副本；以下是独立测试配置，不自动改写用户偏好。

```ini
[DlssNr]
NrBackend=lmxxf
LmxxfAllowEnhancedBarriers=true
NrInline=false
LmxxfEarlyExeWrap=true
```

1. **lmxxf split 基线**：等待加载/网络准备完成后，静止观察 60 秒，再行驶至少 5 分钟。要求视觉 NR 持续生效、没有周期性交替，没有新的 submission failure/device removed。仅菜单显示 ready 不算通过。
2. **Mochizuki split 基线**：完整重启游戏，仅将 `NrBackend=mochizuki`。首次网络构建期间旁路是预期；构建完成后同样观察和行驶，不能继续因 `compute append unsupported` 长期拒绝。
3. **负向策略**：两个后端分别设 `LmxxfAllowEnhancedBarriers=false` 后重启。enhanced 列表应明确拒绝而且游戏原图仍可用，证明显式配置未被覆盖。
4. **扩展矩阵**：依次开启 DRS、切换画质/窗口模式、RT 开/关、多 pass、NR 开/关及后端热切换，至少各 5 分钟；最后单独测 shared effects、FG 与 `NrInline=true`。inline 属额外实验，超时/ahead bypass 必须单独记录，不混入 split 验收结论。
5. **回归对照**：至少一个原本正常的 legacy-barrier 游戏重复单 pass 和后端切换；检查恢复绑定后 SR 与画面没有新异常。

报告各轮“通过/失败/未执行”，附配置、短视频和 `OptiScaler.log`、`amd_bridge.log`、`lmxxf_runtime.log` 或 `mochizuki_nr.log`。日志分享前去除个人路径；不需要上传完整游戏目录。

## 6. 失败时的二次修改顺序

- **仍出现 missing recording proxy**：比较成功/失败的 list 地址和 type。先在创建钩子补 caller module、Create/Create1、open/closed、requested IID、wrap/skip 原因的限频日志，再关联 Execute 中实际提交的列表。type=COMPUTE 需要独立设计 compute-list 支持；不能把它伪装为 DIRECT。若为真正早期未包装列表，按已证实的调用模块收窄修复早期包装，不全局放开所有模块。若为更深 wrapper 链，先确认其解包协议再扩展；当前只增加一层 Streamline 查询。
- **input state unavailable**：先读新增限频日志，核对输入角色、known/invalidated/legacyContract 与 last layout/access。partial 或 aliasing 后未知仍拒绝；未观察输入沿用 caller legacy 契约。若实际布局仅来自前一列表，必须采集真实提交顺序和资源生命周期，再设计跨列表证据，不猜 SRV/COMMON。混合 legacy 输入的 Frame/INI 状态与真实屏障也要核对。
- **enhanced_split_barrier**：当前是整段录制保守拒绝。需要按资源/子资源范围配对 split begin/end 并证明切点无 pending barrier，才可放宽；不能仅统计 begin/end 数量。
- **只剩 rtas 相关异常**：本 PR 已恢复三个 AS 操作的原拒绝策略。先关联被拒绝列表与 NR 评估身份，只有确认同一列表受影响后才单独设计 DXR 放宽和回归；不能因别处有 rtas 日志就认定它是 SR 列表。
- **代理与布局均通过但仍闪烁**：固定 DRS 后检查 frame continuity、history reset、曝光和 runtime 成功/失败；inline 模式另看 timeout/ahead cap。不得通过复用上一帧颜色或隐藏失败日志制造“稳定”。

关闭条件：固定工具链完整构建通过，两种后端在固定分辨率及 DRS 游戏测试中均持续生效，普通 legacy 游戏无回归，剩余状态/错误注入矩阵经维护者验收，且报告准确区分已验证与未覆盖的组合。在满足前保留为待验收修复。
